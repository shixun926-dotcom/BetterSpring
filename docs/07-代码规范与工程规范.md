## 2. 命名规范

| 对象 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 类 | 大驼峰 | `StudentController` | `studentController` |
| 方法 | 小驼峰，动词开头 | `getById`、`listByPage`、`insert` | `student()`、`data()` |
| 变量 | 小驼峰 | `studentService` | `ss`、`a1` |
| 常量 | 全大写下划线 | `MAX_PAGE_SIZE` | `maxPageSize` |
| 包 | 全小写 | `com.campus.controller` | `com.campus.Controller` |
| 数据库表/字段 | 小写下划线 | `class_name` | `className` |
| JSON 字段 | 小驼峰 | `className` | `class_name` |
| Mapper 方法 | 与 SQL 语义一致 | `selectById`、`insertStudent` | `get1` |

⚠️ **易错点**：数据库 `class_name` ↔ Java `className` ↔ JSON `className`。三者映射关系一旦确定（Lv08），**不得再改**。是否开启 MyBatis 驼峰映射（`map-underscore-to-camel-case`）在 [Lv07](levels/Lv07-引入MyBatis.md) 明确。

## 3. 分层边界规范（硬约定）

> 完整职责表见 [04-系统架构 §2](04-系统架构与技术演进.md)。此处是**代码层面的可检查项**。

| # | 规则 | 违反示例 | 检查方式 |
| --- | --- | --- | --- |
| 1 | Controller 不注入 Mapper | `@Autowired StudentMapper mapper;` | 代码审查 / 编译期无检查，靠自觉 |
| 2 | Service 不出现 `Result`、`HttpServletRequest` | `public Result<Student> get(...)` | 返回值必须是业务对象 |
| 3 | Mapper 不写业务 `if` | `if (age > 18) sql...` | 业务判断上移 Service |
| 4 | Entity 不出现在 Controller 方法签名 | `public Result<Student> get()`（`Student` 为 Entity） | 改用 `StudentVO` |
| 5 | `@Transactional` 只在 Service 的 public 方法 | 加在 Controller / private 方法 | 加在 private 上会静默失效 |
| 6 | 依赖注入用构造器 | 字段 `@Autowired` | `GL-004` |
| 7 | 不使用 `System.out.println`，用日志 | `System.out.println(id)` | 全局搜索 |

📌 第 5 条是**最隐蔽的坑**：`@Transactional` 加在 private 方法或同类内部调用上不会生效，且不报错。该实验安排在 [Lv12 §6](levels/Lv12-事务.md)。

## 4. 注解使用规范

| 注解 | 用在哪 | 不用在哪 | 引入关卡 |
| --- | --- | --- | --- |
| `@RestController` | Controller 类 | Service | Lv02 |
| `@Controller` | 需返回视图时（本项目基本不用） | REST 接口 | Lv06 |
| `@Service` | Service 实现类 | Controller | Lv05 |
| `@Repository` | 数据访问类（MyBatis Mapper 通常用 `@Mapper` 即可） | Service | Lv06 |
| `@Mapper` | 每个 Mapper 接口 | — | Lv07 |
| `@MapperScan` | 启动类或配置类 | 每个 Mapper | Lv07 |
| `@Autowired` | 仅当无法用构造器时 | 字段注入（`GL-004` 禁止） | Lv06 |
| `@Transactional` | Service public 方法 | Controller、private、查询方法（只读可加 `readOnly`） | Lv12 |
| `@Valid` | Controller 入参 | Service | Lv15 |
| `@RestControllerAdvice` | 全局异常类 | — | Lv11 |
| `@Aspect` | 切面类 | — | Lv18 |
| `@Component` | 无处归类的 Spring 组件 | 能用 `@Service` 时 | Lv06 |

⚠️ **Lv06 的核心实验**：删掉 `@Service` → 启动 → 看报错 → 加回来。这个实验必须亲手做，否则"Bean 到底是什么"永远是名词。

📎 原始出处（Lv06）：

> 然后专门做一个实验：删掉 @Service ↓ 启动项目 ↓ 看看报什么错 → 再加回来。
> 这个实验会让你真正理解：Bean 到底是什么。

## 5. 异常规范

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 业务异常继承自定义 `BusinessException`，携带 `ErrorCode` | 见 `PKG-common.exception` |
| 2 | Service 抛业务异常，不返回 `null` 表示失败 | 避免调用方到处判空 |
| 3 | Controller 不写 try-catch | 交给 `GlobalExceptionHandler` |
| 4 | 不捕获后吞掉异常（空 catch 块） | 至少记日志 |
| 5 | 面向用户的 `msg` 不得包含堆栈或 SQL | `NFR-002` |
| 6 | 未知异常统一转 `EC-500`，日志打全栈 | 见 [Lv11](levels/Lv11-异常处理.md) |

📎 原始出处（Lv11）：

> Service ↓ throw new XxxException ↓ GlobalExceptionHandler ↓ 统一JSON

## 6. 日志规范

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 使用 `@Slf4j`（Lombok）声明日志对象 | 不手写 `LoggerFactory` |
| 2 | 禁止 `System.out.println` | 见 §3 第 7 条 |
| 3 | 级别使用：`error` 系统故障 / `warn` 业务拒绝 / `info` 关键链路 / `debug` 调试 | — |
| 4 | 日志占位符用 `{}`，不用字符串拼接 | `log.info("id={}", id)` |
| 5 | 不打印密码、Token 全文、完整手机号 | 脱敏 |
| 6 | 接口访问日志由 AOP 统一输出 | 格式见 [Lv18](levels/Lv18-AOP.md) |

📎 原始出处（Lv18 · 访问日志格式）：

> 例如：用户：10001 接口：/student 方法：GET 耗时：32ms

## 7. Git 工作流与提交规范

### 7.1 分支

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定可运行（每个关卡通关后合并） |
| `feat/lvNN-简述` | 单关开发分支 `[推导]` |

🚧 待定：单人学习项目是否值得开分支（见 [附录 B](#附录-b--待决事项)）。

### 7.2 提交信息格式

```
<type>(<scope>): <subject>

type : feat | fix | docs | refactor | test | chore
scope: 模块或包名，如 student、auth、docs
subject: 一句话，中文可用
```

| 示例 | 含义 |
| --- | --- |
| `feat(student): 完成学生 CRUD（Lv09）` | 新增功能 |
| `docs(level): 补全 Lv07 MyBatis 讲义` | 文档变更 |
| `fix(auth): 修复 JWT 过期未返回 401` | 修复 |
| `refactor(layer): Controller 改为只依赖 Service` | 重构 |

📌 提交信息**建议带上关卡号**（`Lv09`），便于把代码历史与关卡进度对齐。

### 7.3 必须提交 / 禁止提交

| ✅ 提交 | ⛔ 不提交（`.gitignore`） |
| --- | --- |
| 源码、`pom.xml`、`application.yml`（**不含真实密码**） | `target/`、`.idea/`、`*.iml` |
| 建表脚本 `db/*.sql` | 本地真实密码文件（`application-local.yml`） |
| Postman 集合导出 | 上传的文件/图片 |
| `docs/` 全量文档 | 日志文件 |

📌 **`docs/` 全量提交**：本文档集是项目资产的一部分，遵循"只追加"原则，历史可追溯。
