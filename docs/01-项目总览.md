## 1. 这是什么

一套 **Spring Boot 实战闯关路线** 的项目文档集。

> **从 0 到一个真正后端项目的完整成长路线。**

每一个关卡都不是"学一个知识点"，而是**完成一个能运行的小目标**。

📎 原始表述（`Consult.txt`）：

> 有，而且我建议直接把这 14 关扩展成一套"Spring Boot 实战闯关路线"。
> 你现在不是缺知识点，而是缺一个东西：每学一个知识点，都能立刻看到它解决了什么问题。
> 所以我们不要做"Spring Boot 知识目录"，而是做一个从 0 到一个真正后端项目的完整成长路线。

## 6. 学习方法论（本路线的灵魂）

参考文档明确要求本路线**不采用"先讲概念"的教法**，而是固定使用两种结构：

### 6.1 每关教学用「5 步教学法」

```
① 先制造问题        new StudentService() 为什么不好？
② 让你自己发现问题   Controller 依赖 Service，Service 依赖 Mapper，Mapper 又依赖其他东西
③ 引入 Spring       @Service
④ 做实验            删掉 @Service → 启动 → 报错 → 恢复 → 启动成功
⑤ 最后才总结        IOC / DI / Bean 的定义
```

📎 原始表述：

> 我特别建议我们之后就按照这个模式学。
> ……这样你学到的东西会非常牢。

📌 完整说明见 [09-关卡教学与交付模板 §2](09-关卡教学与交付模板.md)。

### 6.2 每关交付用「10 步交付格式」

```
① 本关目标 → ② 为什么学 → ③ 环境准备 → ④ 手把手写代码 → ⑤ 让你自己敲
→ ⑥ 故意制造错误 → ⑦ 解释原理 → ⑧ 小练习 → ⑨ 通关标准 → ⑩ 下一关
```

📎 原始表述：

> 每一关我会给你：
> ① 本关目标 → ② 为什么学 → ③ 环境准备 → ④ 手把手写代码 → ⑤ 让你自己敲 → ⑥ 故意制造错误 → ⑦ 解释原理 → ⑧ 小练习 → ⑨ 通关标准 → ⑩ 下一关。

📌 这 10 步就是**每份关卡文档的固定骨架**，对应编号 `LvNN-S1` ~ `LvNN-S10`。见 [09-关卡教学与交付模板 §1](09-关卡教学与交付模板.md)。

### 6.3 通关节奏（强制）

📎 原始表述：

> 你现在直接从 Lv1 开始，**不要提前看后面的内容**。
> 我们就真的把它当成游戏：你完成 Lv1 → 我给你验收 → Lv2 → 验收 → Lv3……

📌 因此：
- 学习时**只打开当前关卡文档**；
- 通关后到 [10-学习进度记录](10-学习进度记录.md) 登记；
- 状态未达 ✅ 前，不进入下一关。

## 7. 项目成功标准（Definition of Done）

一个关卡算完成，当且仅当：

- [ ] §1 目标中的每一条都能亲手复现；
- [ ] §4 代码是自己敲出来的（不是复制的）；
- [ ] §6 的"故意制造错误"实验**真的看到了报错**，并能解释报错含义；
- [ ] §9 的全部验收项 `LvNN-A*` 判定通过；
- [ ] 已在 [10-学习进度记录](10-学习进度记录.md) 登记结论；
- [ ] 若本关改变了架构，已同步 [04-系统架构与技术演进](04-系统架构与技术演进.md)。

整个项目算完成，当且仅当：

- [ ] [02-需求文档](02-需求文档.md) 中标记为"本期必做"的 `FR-*` 全部有对应可运行接口；
- [ ] [06-接口规范](06-接口规范.md) 中登记的 `API-*` 全部在 Postman 集合中可跑通；
- [ ] `docker compose up` 可一键起服务（`Lv24`）；
- [ ] 前端能完成登录、学生列表、成绩查询三条主链路（`Lv25`）。
