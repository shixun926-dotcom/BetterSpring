```
                  Lv10 ─▶ Lv11 ─▶ Lv12 ─▶ Lv13 ─▶ Lv14 ─▶ Lv15 ─▶ Lv16 ─▶ Lv17 ─▶ Lv18 ─▶ Lv19 ─▶ Lv20

```

**跨关依赖（软）**：以下关系不必严格等前置，但越早做越省返工。

| 关系 | 说明 |
| --- | --- |
| Lv16（DTO/VO）↔ Lv10/Lv11 | 若先做 DTO/VO，`Result<T>` 的泛型设计会一次到位 |
| Lv17（拦截器）↔ Lv14（JWT） | Lv14 先手写校验，Lv17 再下沉到拦截器 —— **这个"先脏后净"的过程本身是教学内容，不要跳** |
| Lv18（AOP）↔ Lv12（事务） | 理解 AOP 代理后，才能解释"为什么 `@Transactional` 加在 private 方法上不生效" |

📎 原始出处（Lv17 的"先脏后净"）：

> 第 17 关：拦截器
> 请求 ↓ Interceptor ↓ Controller
> 把 JWT 校验放进去。

## 3. 通关节奏与验收流程

### 3.1 标准流程

```
① 打开当前关卡文档（只打开这一关）
② 读 §1 目标 + §2 为什么学
③ 按 §3 准备环境
④ 看 §4 手把手写代码 → 在 §5 自己敲一遍（不看 §4）
⑤ 做 §6 故意制造错误实验，真的看到报错并解释
⑥ 读 §7 原理解释，用自己的话复述一遍
⑦ 做 §8 小练习
⑧ 按 §9 通关标准逐条打勾
⑨ 到 10-学习进度记录 登记：状态、日期、验收结论、遗留问题
⑩ 只有全部 ✅ 才打开 §10 指向的下一关
```

### 3.2 验收判定

| 判定 | 条件 |
| --- | --- |
| ✅ 通关 | §9 全部 `LvNN-A*` 项通过 |
| 🔁 返工 | 任意一项未通过，修正后重新逐条验收 |
| ⏸ 暂停 | 主动搁置，需在 [10](10-学习进度记录.md) 写明原因与恢复条件 |
| ⛔ 阻塞 | 外部缺失（如 Redis 装不上），需写明缺什么 |

### 3.3 不允许的"通关"

- ⛔ 代码是复制粘贴的，不是自己敲的
- ⛔ "报错我知道什么意思"但从没真看到过报错
- ⛔ §6 实验跳过
- ⛔ 文档里已经写出来的 `API-*` 一个都没在 Postman 跑通
