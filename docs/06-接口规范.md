## 2. 统一返回结构 `Result<T>`

### 2.1 结构定义

```json
{
    "code": 200,
    "msg": "success",
    "data": {}
}
```

📎 原始出处（Lv10）：

> 我们统一：
> { "code": 200, "msg": "success", "data": {} }
> 创建：Result<T>
> public class Result<T> { private Integer code; private String msg; private T data; }
> 以后：return Result.success(student);

### 2.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `Integer` | 是 | 业务状态码，见 §3 |
| `msg` | `String` | 是 | 提示信息。成功固定 `"success"`；失败为可展示的中文（如 `"学生不存在"`） |
| `data` | `T` | 否 | 业务数据。无数据时为 `null`（**不要返回 `{}` 或 `""`**） |

### 2.3 静态工厂方法约定

| 方法 | 产生 | 对应 `code` |
| --- | --- | --- |
| `Result.success()` | 成功、无数据 | 200 |
| `Result.success(T data)` | 成功、带数据 | 200 |
| `Result.error(Integer code, String msg)` | 失败 | 见 §3 |
| `Result.error(ErrorCode ec)` | 失败（用枚举） | 见 §3 |

📌 方法名与签名在 Lv10 首次实现时**冻结**。后续新增方法（如 `Result.success(msg, data)`）只能追加，不得改已有签名。

### 2.4 正例 / 反例

```jsonc
// ✅ 查询单个学生成功
{ "code": 200, "msg": "success", "data": { "id": 1, "name": "张三", "age": 20, "gender": "M", "className": "计科2101" } }

// ✅ 新增成功
{ "code": 200, "msg": "success", "data": null }

// ✅ 学生不存在
{ "code": 404, "msg": "学生不存在", "data": null }

// ✅ 分页查询成功
{ "code": 200, "msg": "success", "data": { "total": 57, "page": 1, "pageSize": 10, "list": [] } }

// ⛔ 反例：直接返回实体
{ "id": 1, "name": "张三" }

// ⛔ 反例：直接返回字符串（Lv10 之前的老写法）
"success"

// ⛔ 反例：返回异常堆栈
{ "timestamp": "...", "status": 500, "error": "Internal Server Error", "trace": "java.lang.NullPointerException..." }
```

📎 原始出处（反例来源，Lv10）：

> 你现在可能：return student; 有时候：return "success"; 这不规范。

## 3. 状态码表 `EC-*`

📌 `code` 使用**业务语义码**，与 HTTP 状态码解耦但要**保持大致一致**，避免前端两套逻辑。

| `EC` | `code` | `msg` 示例 | 使用场景 | 引入关卡 |
| --- | --- | --- | --- | --- |
| `EC-200` | 200 | `success` | 一切成功 | Lv10 |
| `EC-400` | 400 | `参数校验失败` | 参数缺失/格式错误/校验不通过 | Lv11、Lv15 |
| `EC-401` | 401 | `未登录或登录已过期` | 无 Token / Token 无效 / Token 过期 | Lv14 |
| `EC-403` | 403 | `无权限访问` | 已登录但角色不足 | Lv21 |
| `EC-404` | 404 | `学生不存在` | 资源不存在 | Lv11 |
| `EC-409` | 409 | `数据已存在` | 唯一约束冲突（如重复选课） | 第九阶段 |
| `EC-500` | 500 | `服务器内部错误` | 未预期异常 | Lv11 |

📎 原始出处（Lv11）：

> 例如：
> { "code": 404, "msg": "学生不存在", "data": null }

⚠️ **HTTP 状态码与 `code` 的关系必须在本节末尾明确一次**（待定）：是"HTTP 永远 200，业务码放 body"，还是"两者都设"。该决定会影响前端处理逻辑，见 [附录 B B.1](#附录-b--待决事项)。

### 4.1 请求参数

## 5. 认证约定

| 项 | 约定 |
| --- | --- |
| 请求头 | `Authorization: Bearer <jwt>` |
| 白名单（无需 Token） | `POST /auth/login`、`POST /auth/code`、`POST /auth/register` 🚧 待定路径 |
| Token 失效 | 返回 `{ "code": 401, "msg": "未登录或登录已过期", "data": null }` |
| Token 位置 | **只允许请求头**，禁止 URL 携带（`NFR-004`） |
| 用户身份传递 | 解析出的用户 ID 放入请求上下文，Service 通过上下文获取，不从 Controller 透传 `HttpServletRequest` |

📎 原始出处（Lv14）：

> 以后访问：GET /student 需要：Authorization: Bearer xxx
> 后端：JWT ↓ 解析 ↓ 获取用户ID ↓ 判断身份 ↓ 允许访问

🚧 待补充：拦截器实现后本节的"上下文获取方式"一节（对应 Lv17）。
