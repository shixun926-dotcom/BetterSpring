## 3. 选型理由与替代方案

📌 每一行问三个问题：**为什么是它？不用它会怎样？替代方案是什么？**

| 技术 | 为什么需要它（解决什么问题） | 替代方案 | 出现在哪一关的对照 |
| --- | --- | --- | --- |
| Spring Boot | 不用它：要自己配 Tomcat、自己管依赖版本、自己写 web.xml | 原生 Spring + Tomcat | Lv01 |
| Spring MVC | 把 Java 方法变成 HTTP 接口 | Servlet / JAX-RS | Lv02、Lv03 |
| Service 层 | 不用它：Controller 里查询/校验/业务/返回混在一起，30 个接口就崩 | 无（这是分层，不是库） | Lv04 |
| IOC / DI | 不用它：到处 `new`，依赖写死，无法替换与测试 | 手写工厂 | Lv05、Lv06 |
| MyBatis | 不用它：手写 JDBC 的 `Connection` / `PreparedStatement` / `ResultSet` 映射 | JPA / Hibernate、JdbcTemplate | Lv07 |
| MySQL | 数据要落盘、要持久 | PostgreSQL / H2 | Lv08 |
| Result<T> | 不用它：有时返回对象、有时返回字符串，前端无法统一处理 | 直接返回实体 | Lv10 |
| 全局异常处理 | 不用它：异常堆栈直接吐给浏览器 | try-catch 到处写 | Lv11 |
| @Transactional | 不用它：A 扣钱成功、B 加钱失败时数据不一致 | 手写 commit/rollback | Lv12 |
| Redis | 不用它：验证码存内存重启即丢、多实例不一致；也无法设过期 | 数据库表 + 定时清理、Session | Lv13 |
| JWT | 不用它：Session 在分布式/多实例下需要共享存储 | Session + Redis、OAuth2 | Lv14 |
| 参数校验 | 不用它：每个接口里写一堆 if 判空 | 手写 if | Lv15 |
| DTO / VO | 不用它：实体直接进出，数据库结构暴露给前端，改表即改接口 | 直接用 Entity | Lv16 |
| 拦截器 | 不用它：每个 Controller 方法开头都写一遍 Token 校验 | Filter、AOP | Lv17 |
| AOP | 不用它：日志代码散落在每个方法里 | 手写日志工具方法 | Lv18 |
| 分页 | 不用它：全表返回，数据量一大直接 OOM | 内存分页 | Lv19 |
| 文件上传 | 不用它：图片存数据库或 Base64 塞进 JSON | 无 | Lv20 |

📌 上表是 [00-维护规范 §7](00-文档使用与维护规范.md)「每个知识点必须回答：没有它会发生什么问题」的落地位置。新增技术时**必须补一行**。
