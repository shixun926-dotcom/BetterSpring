## 1. 这套文档解决什么问题

参考文档给出的核心判断是：

> 你现在不是缺知识点，而是缺一个东西：
> **每学一个知识点，都能立刻看到它解决了什么问题。**

所以这套文档**不是**「Spring Boot 知识目录」，而是：

> 一个从 0 到一个真正后端项目的完整成长路线，且**可验收、可追踪、可增补**。

三个设计目标：

| 目标 | 落地方式 |
| --- | --- |
| 每个知识点都有"它解决了什么问题" | 每关固定「5 步教学法」+「10 步交付格式」 |
| 每一关都能验收 | 每关都有独立的《通关标准》，并在 [10-学习进度记录](10-学习进度记录.md) 留痕 |
| 学到一半可以随时加东西而不破坏前面 | 全文档编号稳定 + 追加区 + 变更记录 |

## 4. 三条阅读路径

### 路径 A · 按关卡顺序学（默认，推荐）

严格按参考文档的建议执行：

> 你现在直接从 Lv1 开始，**不要提前看后面的内容**。
> 我们就真的把它当成游戏：你完成 Lv1 → 我给你验收 → Lv2 → 验收 → Lv3……

```
00 规范 → 03 环境准备 → 08 关卡总览（只看 Lv1 这一行）
        → levels/Lv01 → 10 进度记录打卡 → levels/Lv02 → …
```

### 路径 B · 需要查资料时

```
某个注解/概念不懂  → 11 术语表 定位 → 对应主文档章节 → 对应关卡 §7 原理解释
某个接口不确定    → 06 接口规范
某张表不确定      → 05 数据库设计
不知道代码该放哪  → 07 代码规范 §1 包结构 / §3 分层边界
```

### 路径 C · 复习与查漏

```
08 关卡总览 → 挑出状态为 ✅ 但记忆模糊的关卡 → 直接读该关 §6 故意制造错误 + §9 通关标准
```
