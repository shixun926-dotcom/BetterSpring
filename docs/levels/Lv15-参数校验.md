## 2. 为什么学 `Lv15-S2`

先制造问题。现在你的新增接口是这样的：

```java
@PostMapping
public Result<Void> add(@RequestBody Student student) {
    studentService.add(student);
    return Result.success();
}
```

前端传来：

```json
{ "name": "", "age": -5, "gender": "不知道", "className": "这是一个非常非常非常非常长的班级名字……" }
```

**它会照单全收地写进数据库。**

不用 `@Valid` 的话，你只能在 Service 里写：

```java
public void add(Student s) {
    if (s.getName() == null || s.getName().trim().isEmpty()) throw new BusinessException(..., "姓名不能为空");
    if (s.getName().length() > 50) throw new BusinessException(..., "姓名过长");
    if (s.getAge() == null || s.getAge() < 0 || s.getAge() > 150) throw new BusinessException(..., "年龄不合法");
    if (s.getGender() == null || !VALID_GENDERS.contains(s.getGender())) throw new BusinessException(..., "性别不合法");
    // ... 而这些，每个写接口都要重写一遍
}
```

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | 判空代码在每个接口重复 | 改规则要改 N 处 |
| 2 | 校验逻辑与业务逻辑混在一起 | Service 被噪声淹没 |
| 3 | 规则的"声明"与"实现"分离 | 看 DTO 完全看不出有哪些约束 |
| 4 | 容易漏 | 漏一个就脏数据入库 |

**参数校验注解解决的就是这些**：把约束**声明在字段上**，由框架统一执行。

📌 关键判断：**校验是"入口契约"，不是"业务逻辑"。** 所以它属于 Controller 的入参，不属于 Service。

## 4. 手把手写代码 `Lv15-S4`

### 4.1 写校验注解

```java
package com.campus.dto;

import jakarta.validation.constraints.*;
import lombok.Data;

@Data
public class StudentDTO {

    @NotBlank(message = "姓名不能为空")
    @Size(max = 50, message = "姓名长度不能超过 50")
    private String name;

    @NotNull(message = "年龄不能为空")
    @Min(value = 0, message = "年龄不能小于 0")
    @Max(value = 150, message = "年龄不能大于 150")
    private Integer age;

    @NotBlank(message = "性别不能为空")
    @Pattern(regexp = "M|F|U", message = "性别只能是 M/F/U")   // 取值以 05 §3.3 为准
    private String gender;

    @Size(max = 50, message = "班级名称过长")
    private String className;
}
```

📌 `jakarta.validation.*` —— Spring Boot 3 用的是 `jakarta`，不是 `javax`。

### 4.2 在 Controller 上触发

```java
@PostMapping
public Result<Void> add(@Valid @RequestBody StudentDTO student) {
    studentService.add(student);
    return Result.success();
}
```

📎 参考（`Consult.txt`）：

> 例如：

>         @Valid @RequestBody StudentDTO student

### 4.3 把校验失败接进全局异常处理器

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
public Result<Void> handleValid(MethodArgumentNotValidException e) {
    // 🚧 待补充：从 e.getBindingResult().getFieldErrors() 取出第一条错误信息
    // return Result.error(ErrorCode.PARAM_ERROR.getCode(), msg);
}
```

📌 关键设计：**返回给前端的 `msg` 应该是你在注解里写的那句话**（"年龄不能大于 150"），而不是 Spring 默认的长篇英文报错。

### 4.4 运行与验证

```
① 正常入参
POST /students  {"name":"张三","age":20,"gender":"M","className":"计科2101"}
→ { "code":200, "msg":"success", "data":null }

② 姓名为空
POST /students  {"name":"","age":20,"gender":"M"}
→ { "code":400, "msg":"姓名不能为空", "data":null }

③ 年龄越界
POST /students  {"name":"张三","age":200,"gender":"M"}
→ { "code":400, "msg":"年龄不能大于 150", "data":null }
```
