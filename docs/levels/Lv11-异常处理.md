## 2. 为什么学 `Lv11-S2`

先制造问题。

Service 里现在是这样：

```java
public Student getStudent(Integer id) {
    return studentMapper.getById(id);      // 查不到时返回 null
}
```

Controller 里收到 `null`，包成 `Result.success(null)`，前端显示"查询成功"。

**方案 A：在 Controller 里判空**

```java
Student s = studentService.getStudent(id);
if (s == null) return Result.error(404, "学生不存在");
```

问题：**30 个接口就要写 30 遍**，而且每个接口的"什么情况算异常"都不一样。

**方案 B：在 Service 里直接抛异常**

```java
public Student getStudent(Integer id) {
    Student s = studentMapper.getById(id);
    if (s == null) throw new RuntimeException("学生不存在");
    return s;
}
```

问题：浏览器收到完整堆栈：

```json
{
  "timestamp": "2026-09-14T10:00:00.000+00:00",
  "status": 500,
  "error": "Internal Server Error",
  "trace": "java.lang.RuntimeException: 学生不存在\n\tat com.campus.service...",
  "path": "/students/99999"
}
```

**这一坨东西有三个问题：**
1. 前端解析不了（结构与 `Result` 完全不同）；
2. 暴露了类名、包名、SQL 等内部信息（`NFR-002`）；
3. 每个异常都变成 500，前端无法区分"用户输错了"和"服务器挂了"。

📌 正确做法：**Service 只管抛，出口统一由全局处理器负责。**

📌 参考文档的判断很直接：

> 这一关之后，你的项目味道就出来了。

### 4.2 自定义业务异常

```java
package com.campus.common.exception;

import com.campus.common.ErrorCode;
import lombok.Getter;

@Getter
public class BusinessException extends RuntimeException {

    private final Integer code;

    public BusinessException(ErrorCode ec) {
        super(ec.getMsg());
        this.code = ec.getCode();
    }

    public BusinessException(ErrorCode ec, String msg) {
        super(msg);
        this.code = ec.getCode();
    }
}
```

### 4.4 Service 改为抛异常

```java
public Student getStudent(Integer id) {
    Student student = studentMapper.getById(id);
    if (student == null) {
        throw new BusinessException(ErrorCode.NOT_FOUND, "学生不存在");
    }
    return student;
}
```

>  ↓
> GlobalExceptionHandler
>  ↓
> 统一JSON

### 4.5 三类异常的处理策略（本关核心设计）

| 异常类型 | 对应 `code` | 前端看到什么 | 日志级别 |
| --- | --- | --- | --- |
| `BusinessException` | 用异常自带的 `code` | 具体业务提示，如"学生不存在" | `warn` |
| 参数类异常（`Lv15` 引入） | 400 | 具体哪个字段不合法 | `warn` |
| 其它 `Exception` | 500 | 只看到"服务器内部错误"，**不带细节** | `error`（记全栈） |

## 10. 下一关 `Lv11-S10`

现在你的项目"味道出来了"：统一返回 + 统一异常。

但有一类问题它完全防不住。假设有一个转账操作：

```
A 账户 -100      ← 执行成功
B 账户 +100      ← 失败了
```

第一个操作已经写进数据库了，第二个没有。**A 的钱凭空消失了。**

你的代码没有任何地方能阻止这件事 —— 因为 `updateA()` 和 `updateB()` 是两次独立的数据库操作，第一次提交之后就不会再回头。
