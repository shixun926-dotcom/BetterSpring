## 2. 为什么学 `Lv17-S2`

先制造问题。Lv16 结束时，每个受保护接口都是这样：

```java
@GetMapping
public Result<List<StudentVO>> list(@RequestHeader(value = "Authorization", required = false) String auth) {
    if (auth == null || !auth.startsWith("Bearer ")) throw new BusinessException(ErrorCode.UNAUTHORIZED);
    Long userId = jwtUtil.parseUserId(auth.substring(7));
    if (userId == null) throw new BusinessException(ErrorCode.UNAUTHORIZED);
    // ↑ 以上四行，与业务无关
    return Result.success(studentService.list());
}
```

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | 5 个接口写 5 遍 | 改成"解析失败也要记日志"时要改 5 处 |
| 2 | 20 个接口写 20 遍 | 漏一个就是**一个无认证的后门** |
| 3 | 加"仅管理员可访问" | 每个接口再写一遍角色判断 |
| 4 | Controller 签名被污染 | 每个方法都多一个 `auth` 参数 |
| 5 | Service 拿不到当前用户 | 想把 `userId` 传给 Service 只能一路透传 |

**拦截器解决的就是前四条**：所有请求先经过一个统一的地方，校验逻辑只写一次。

📌 本关的验收标准很特别：**代码行数要变少。**
如果重构之后代码更多了，说明没做对。

### 4.2 拦截器

```java
package com.campus.interceptor;

@Component
public class AuthInterceptor implements HandlerInterceptor {

    private final JwtUtil jwtUtil;

    public AuthInterceptor(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        // 🚧 待补充：
        // 1. 从 Header 取 Authorization
        // 2. 校验 Bearer 前缀
        // 3. 解析出 userId，失败则抛 BusinessException(UNAUTHORIZED)
        // 4. 成功：把 userId 放入请求上下文（见 §4.4）
        // 5. return true 放行
        return true;
    }
}
```

### 4.3 注册与白名单

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    private final AuthInterceptor authInterceptor;

    public WebMvcConfig(AuthInterceptor authInterceptor) {
        this.authInterceptor = authInterceptor;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(authInterceptor)
                .addPathPatterns("/**")
                .excludePathPatterns(
                        "/auth/login",
                        "/auth/code"
                        // 🚧 待补充：注册、错误页、静态资源等
                );
    }
}
```

⚠️ **白名单漏配 = 接口打不开；白名单多配 = 后门。** 每加一个接口都要想一次"它在不在白名单里"。

### 4.4 身份传递（本关的设计决策）

Service 需要知道"当前用户是谁"，有三种做法：

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| A. Controller 透传 | 每个方法多一个 `Long userId` 参数 | 能跑，但污染签名 |
| B. `ThreadLocal` | 拦截器写入，Service 读取 | ✅ 常见做法，注意请求结束时清理 |
| C. `HttpServletRequest` 透传 | Service 接收 request | ⛔ 违反 [04 §6](../04-系统架构与技术演进.md#6-边界与硬约定) 第 2 条 |

📌 方案选定后写入 [06 §5 认证约定](../06-接口规范.md#5-认证约定)（该节已留"🚧 待补充：拦截器实现后本节的上下文获取方式"）。

🚧 待补充：本项目最终选择与实现。

## 10. 下一关 `Lv17-S10`

拦截器解决了"请求进来之前先做点什么"。

但还有一类需求它管不了。参考文档给了一个例子：

```
用户：10001
接口：/student
方法：GET
耗时：32ms
```

**你想给每个接口都记这样一条日志。**

用拦截器能做吗？能做 —— 但你拿不到"方法执行了多久"的准确边界（`postHandle` 在异常时不会执行），也拿不到具体调用了哪个类的哪个方法。

而且拦截器只能拦"HTTP 请求"，如果你的 Service 方法也需要统一加逻辑呢？
