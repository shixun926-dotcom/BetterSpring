## 2. 为什么学 `Lv20-S2`

先制造问题。

参考文档给出的链路很直白：

```
头像上传 → 服务器 / OSS → 返回URL → MySQL保存URL
```

但如果你没想过，很自然会写出这些"能跑但会出事"的做法：

| # | 常见做法 | 问题 |
| --- | --- | --- |
| 1 | 把图片转成 Base64 塞进 JSON | 体积膨胀约 33%，数据库被撑爆，JSON 响应巨大 |
| 2 | 把文件二进制直接存进 MySQL `BLOB` | 数据库体积失控、备份极慢、读一张图要占连接 |
| 3 | 存到服务器硬盘，但**用原始文件名** | 同名覆盖、路径穿越攻击（`../../`） |
| 4 | 存到服务器硬盘，但**不返回可访问 URL** | 前端拿不到图 |
| 5 | 不校验文件类型 | 上传 `.jsp` / `.php` / `.exe`，配合解析漏洞可执行 |
| 6 | 多台服务器各存各的 | A 机器上传的图，B 机器上访问不到 |

**正确做法**：文件放**专门的文件存储**（本地目录规划好，或对象存储 OSS），数据库只存**URL**。

📌 为什么数据库只存 URL：

| 理由 | 说明 |
| --- | --- |
| 数据库擅长结构化数据 | 存大二进制会让行变大、索引变差、备份变慢 |
| 文件存储可以横向扩展 | OSS 天然带 CDN、冗余、限流 |
| 换存储方案不用改表 | 只换 URL 前缀 |

**参考文档说"从 Lv15 到 Lv20，就是从'会写'变成'像公司'"。现在这段路走完了。**

但有一个问题一直没解决。

你的权限判断现在是这样的（[Lv17](Lv17-拦截器.md) 里写的）：

```java
// 拦截器里：所有登录用户一视同仁
if (tokenInvalid) return 401;
```

**那"只有管理员能删除学生"怎么办？**

你现在大概会在拦截器里加一堆 `if (path.startsWith("/admin"))`。三个角色还好，十个角色、二十个接口之后，这个拦截器会长成一个怪物 —— 而且**每一个新接口都要被想起来加一次判断，漏一次就是一个越权漏洞**。

下一关：**Spring Security**。
