## 2. 为什么学 `Lv18-S2`

先制造问题。

你要给每个接口记录"谁、访问了什么、耗时多少"。不用 AOP，你能怎么做？

**方案一：每个方法里手写**

```java
@GetMapping
public Result<List<StudentVO>> list() {
    long start = System.currentTimeMillis();
    log.info("用户={} 接口=/students 方法=GET", currentUserId());
    try {
        return Result.success(studentService.list());
    } finally {
        log.info("耗时={}ms", System.currentTimeMillis() - start);
    }
}
```

问题：**20 个接口写 20 遍**；而且一旦业务代码抛异常，`return` 走不到，日志逻辑就乱了。

**方案二：拦截器**

Lv17 已经有一个了，可以扩展。但：

| # | 限制 | 说明 |
| --- | --- | --- |
| 1 | 只覆盖 HTTP 请求 | Service 方法、定时任务、MQ 消费者全都管不到 |
| 2 | 拿不到"具体执行的类和方法" | 只能拿到 URI |
| 3 | 耗时边界不准 | `postHandle` 在 Controller 抛异常时**不执行** |
| 4 | 无法在"方法真正的执行前后"插入逻辑 | 是 Servlet 层的概念 |

**AOP 解决的就是这些**：它是**方法级**的，与"是不是 HTTP 请求"无关。

📌 一句话区分：

> **拦截器管"请求"，AOP 管"方法调用"。**

## 4. 手把手写代码 `Lv18-S4`

### 4.1 目录结构

```
com/campus
└── aspect
    └── LogAspect.java       ← 本关新增
```

### 4.2 切面

```java
package com.campus.aspect;

@Slf4j
@Aspect
@Component
public class LogAspect {

    @Around("execution(* com.campus.controller..*(..))")
    public Object logAround(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        // 🚧 待补充：
        // 1. 取出请求信息（URI / HTTP 方法）—— 可从 RequestContextHolder 取
        // 2. 取出当前用户ID
        // 3. pjp.proceed() 执行目标方法
        // 4. finally 中输出：用户 / 接口 / 方法 / 耗时
        return pjp.proceed();
    }
}
```

### 4.3 目标日志格式

📎 参考（`Consult.txt` · 期望输出）：

> 用户：10001
> 接口：/student
> 方法：GET
> 耗时：32ms

📌 输出格式**必须与上面四行一致**（这是 [07 §6](../07-代码规范与工程规范.md#6-日志规范) 第 6 条的来源）。

### 4.4 切点表达式解读（本关必答）

```java
@Around("execution(* com.campus.controller..*(..))")
```

| 部分 | 含义 |
| --- | --- |
| `execution(...)` | 切点指示符：按方法签名匹配 |
| 第一个 `*` | 返回值类型不限 |
| `com.campus.controller..` | 包及其**所有子包** |
| `*` | 任意类 |
| `(..)` | 任意参数 |

🚧 待补充：把你实际使用的表达式与本表对齐，并说明为什么这样切。

### 4.5 五种通知类型对照

| 通知 | 注解 | 执行时机 |
| --- | --- | --- |
| 前置 | `@Before` | 目标方法调用前 |
| 后置返回 | `@AfterReturning` | 目标方法正常返回后 |
| 后置异常 | `@AfterThrowing` | 目标方法抛异常后 |
| 后置最终 | `@After` | 无论成功失败都执行（类似 `finally`） |
| 环绕 | `@Around` | 包住整个调用，可决定是否执行、可改返回值 |

📌 本关用 `@Around`，因为需要"前后都插逻辑 + 精确耗时"。

### 4.6 运行与验证

```
① 带 Token 请求 GET /students
② 控制台应输出：
   用户：10001 接口：/students 方法：GET 耗时：32ms
③ 让接口抛异常，确认耗时日志**仍然输出**
```

📌 第 ③ 条正是拦截器做不到的。
