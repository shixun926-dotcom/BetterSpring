## 2. 为什么学 `Lv10-S2`

先制造问题。Lv09 结束时，前端会收到这些东西：

| 请求 | 现在返回什么 | 前端要写多少分支 |
| --- | --- | --- |
| `GET /students/1` | `{"id":1,"name":"张三",...}` | 判断这是不是一个学生 |
| `GET /students` | `[{...},{...}]` | 判断这是不是一个数组 |
| `POST /students` | `"添加成功"` | 判断这是一句话 |
| `DELETE /students/1` | `"删除成功"` | 再判断一次 |
| 出错时 | Spring 默认错误 JSON（含 `timestamp`/`trace`） | 又一套完全不同的结构 |

**问题**：前端要为每个接口写不同的解析逻辑；而且**想知道"成功还是失败"，只能靠 HTTP 状态码或猜**。

企业里没人这么干。统一成：

```json
{ "code": 200, "msg": "success", "data": {} }
```

前端一套逻辑处理所有接口：

```js
if (res.code === 200) { use(res.data) } else { toast(res.msg) }
```

📌 参考文档把这关放在"开始接触公司代码"的阶段，含义很明确：
**从这里开始，你不是在"让功能跑起来"，而是在"让代码能被别人接手"。**

### 4.2 `Result<T>`

import lombok.Data;

@Data
public class Result<T> {

📎 参考（`Consult.txt` · `Result<T>` 的骨架）：

### 4.4 Controller 改造

```java
@GetMapping("/{id}")
public Result<Student> get(@PathVariable Integer id) {
    return Result.success(studentService.getStudent(id));
}

@PostMapping
public Result<Void> add(@RequestBody Student student) {
    studentService.add(student);
    return Result.success();
}

@GetMapping
public Result<List<Student>> list() {
    return Result.success(studentService.list());
}
```

📌 注意 `Result<Void>` 与 `Result.success()`（`data` 为 `null`），对应 [06 §2.4](../06-接口规范.md#24-正例--反例) 的约定：**无数据时返回 `null`，不要返回 `{}` 或 `""`**。

### 4.5 运行与验证

```
GET /students/1
→ { "code": 200, "msg": "success", "data": { "id":1, "name":"张三", ... } }

POST /students
→ { "code": 200, "msg": "success", "data": null }
```

🚧 待补充：实际返回值粘贴。

⚠️ 此刻"学生不存在"会返回什么？`data: null` 但 `code: 200` —— **这不对**。
这个问题留给 Lv11 解决。**本关不要提前做异常处理。**

## 10. 下一关 `Lv10-S10`

统一返回做好了，但你没解决一件事：

**查询一个不存在的学生时，接口返回了 `{ "code": 200, "msg": "success", "data": null }`。**

前端会说："查询成功，数据为空。"

这在业务上是**错的** —— 应该是"学生不存在"。

而如果你现在去 Service 里 `throw new RuntimeException("学生不存在")`，浏览器会收到一坨堆栈。

下一关：**异常处理**。
